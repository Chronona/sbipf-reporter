ADR-0002: CSV構造の判定を位置ベースから名前ベースに変える
=======================================================

:状態: 採用
:日付: 2026-09-17

背景
----

修正前のパーサーは、CSV の構造を次のように決め打ちで判定していた。

* セクション見出し: ``株式（`` または ``投資信託（`` で始まる行（全角括弧のみ）
* 列位置: 「参考単価」の有無で 11 列版 / 10 列版のインデックスを固定
* 投資信託の判別: 銘柄名が ``ｅＭＡＸＩＳ`` / ``ｉＦｒｅｅ`` / ``ＳＢＩ・``
  のいずれかで始まるか
* 数値: ``float()`` にそのまま渡す

この決め打ちが、実際の CSV のゆれで破綻することを確認した。

* SBI証券のCSVは同じ見出しを全角・半角の両方で出力する
  （見出しは ``株式（現物/特定預り）`` だが合計行は ``株式(現物/特定預り)合計``）。
  半角括弧の見出しはセクションとして認識されず、口座区分が全件 ``UNKNOWN`` になる。
* ``外国株式（…）`` のように ``株式（`` で始まらないセクションは見出しとして
  認識されず、直前のセクションの口座区分を引きずったまま行が取り込まれる。
* ハードコードされた 3 プレフィックス以外の投信
  （``たわらノーロード 先進国株式`` など）は、銘柄名が最初の空白で分割され
  ``code="たわらノーロード", name="先進国株式"`` となる。
* 桁区切りカンマ付きの数値は ``float()`` が失敗し、``except: continue`` で
  行ごと無言で捨てられる。全行がこの形式だと結果が 0 件になるが、何も表示されない。

決定
----

構造の判定を、位置や銘柄名ではなく **CSV自身が持つ名前** から行う。

セクション見出し
  「1セルだけが埋まった行」かつ ``<資産種別>(<取引区分>/<預り区分>)`` の形
  であることを、NFKC 正規化した文字列に対する正規表現で判定する。
  資産種別を限定しないので ``外国株式`` や ``債券`` のセクションも検出できる。

口座区分
  見出しの括弧内、さらに ``/`` 以降の預り区分だけを見て判定する。
  NISA を特定より先に判定し、両方の語を含む見出しでも誤判定しない。

列位置
  ヘッダー行の列名（買付日 / 数量 / 取得単価 / 現在値 / 損益 / 評価額）で
  インデックスを解決する。「損益」と「損益（％）」は正規化後の完全一致で
  区別する。列名で解決できなかった場合のみ、従来の位置ベース推定に
  フォールバックする。

株式 / 投資信託の判別
  銘柄名のプレフィックスではなく、列ヘッダーが ``ファンド名`` か
  ``銘柄（コード）`` かで判別する。投信はセル全体を銘柄名として扱う。

数値
  NFKC 正規化のうえ桁区切りカンマと通貨記号を除去してから変換する。
  ``--`` などのプレースホルダーは数値として扱わない。

パース失敗行
  読み飛ばす点は変えないが、``UserWarning`` を送出して黙って消えないようにする。

影響
----

* 既存フィクスチャのパース結果は変わらない（回帰テストで確認済み）。
* 半角括弧・非株式セクション・未知の投信名・桁区切り数値を含む CSV で
  結果が変わる（いずれも修正前は誤りだった）。
* パース不能な行があると警告が出る。CI でこれをエラーにしたい場合は
  ``warnings.simplefilter("error")`` を使う。
