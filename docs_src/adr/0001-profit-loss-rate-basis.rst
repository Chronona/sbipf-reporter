ADR-0001: 損益率の分母を取得金額に統一する
==============================================

:状態: 採用
:日付: 2026-09-17

背景
----

修正前は、損益率の計算基準が2箇所で食い違っていた。

* ``Holding.profit_loss_rate``: ``損益 ÷ 評価額``
* ``format_as_markdown`` / ``print_summary`` の合計行: ``損益 ÷ (評価額 - 損益)``

``評価額 - 損益`` は取得金額である。つまり銘柄ごとの損益率とポートフォリオ
合計の損益率が別の定義になっており、同じレポート内で行と合計が整合しなかった。
利益が出ている銘柄では行の損益率が実際より小さく表示されていた
（例: 取得 10,000 円 → 評価 11,000 円 で 10.00% ではなく 9.09%）。

さらに ``print_summary`` は分母が 0 のときガードが効かず
``ZeroDivisionError`` で異常終了していた。

決定
----

損益率の分母を **取得金額** に統一する。

* ``Holding.acquisition_cost`` を追加し、``評価額 - 損益`` で取得金額を求める。
* ``Holding.profit_loss_rate`` は ``損益 ÷ 取得金額 × 100`` とする。
* 合計値の算出は ``sbipf_reporter.summary.summarize()`` に一本化し、
  ターミナル表示と Markdown 出力が同じ実装を共有する。
* 分母が 0 の場合は例外を送出せず 0.0 を返す。

取得単価 × 数量 ではなく ``評価額 - 損益`` を採用したのは、CSV が出力した
評価額・損益と必ず整合するため。取得単価は表示桁で丸められている場合があり、
掛け算で求めると合計が合わなくなる。

影響
----

* 損益率の表示値が変わる（ターミナル / Markdown / CSV のすべて）。
  利益局面では従来より大きい値、損失局面では従来より小さい値になる。
* 公開APIに ``acquisition_cost`` / ``PortfolioSummary`` / ``summarize`` が増える。
  既存のフィールドとシグネチャに破壊的変更はない。
