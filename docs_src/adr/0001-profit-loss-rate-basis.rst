ADR-0001: 損益率の分母を取得金額に統一する
==========================================================

:状態: 採用
:日付: 2026-09-20
:関連: Issue #40

背景
----

損益率の計算基準が2箇所で食い違っていた。

* ``Holding.profit_loss_rate``: ``損益 ÷ 評価額``
* ``print_summary`` / ``format_as_markdown`` の合計行: ``損益 ÷ (評価額 - 損益)``

``評価額 - 損益`` は取得金額である。つまり銘柄ごとの損益率とポートフォリオ
合計の損益率が別の定義になっており、同じレポート内で行と合計が整合しなかった。

利益が出ている銘柄では、行の損益率が実際より小さく表示されていた。
例えば取得 10,000 円 → 評価 11,000 円（損益 +1,000 円）の銘柄は、
本来 10.00% のところ 9.09% と表示されていた。

決定
----

損益率の分母を **取得金額** に統一する。

* ``Holding.acquisition_cost`` を追加し、``評価額 - 損益`` で取得金額を求める。
* ``Holding.profit_loss_rate`` は ``損益 ÷ 取得金額 × 100`` とする。
* 取得金額が 0 の場合は例外を送出せず 0.0 を返す。

取得金額を ``取得単価 × 数量`` ではなく ``評価額 - 損益`` で求めるのは、
CSV が出力した評価額・損益と必ず整合するためである。取得単価は表示桁で
丸められている場合があり、掛け算で求めると個々の行と合計が合わなくなる。

CSV の「損益（％）」カラムをそのまま使わないのは、このカラムの値が
フォーマットによって基準が異なる可能性があり、また列レイアウトの
判定対象を増やしたくないためである。評価額と損益から再計算すれば
CSV 内で完結して整合する。

影響
----

* 損益率の表示値が変わる（ターミナル / Markdown / CSV のすべて）。
  利益局面では従来より大きい値、損失局面では従来より小さい値になる。
* 公開APIに ``Holding.acquisition_cost`` が増える。
  既存のフィールドとシグネチャに破壊的変更はない。
* バージョンは据え置いている。表示値が変わるため、いずれ 0.5.0 への
  bump が必要だが、それは別途判断する。

備考
----

この決定により、行の損益率と合計の損益率が同じ基準になる。
ただし合計の算出は ``formatter.py`` と ``reporter.py`` に別実装で
残っているため、将来また分岐しうる。その一本化は Issue #41 で扱う。
