ADR-0002: ポートフォリオ合計の算出を単一モジュールに一本化する
==============================================================================

:状態: 採用
:日付: 2026-09-21
:関連: Issue #41、ADR-0001

背景
----

ポートフォリオ合計の損益率が、出力フォーマットごとに別々の実装で
計算されていた。

``formatter.py``（ターミナル表示）::

    total_rate = (total_profit / total_cost * 100) if total_cost != 0 else 0.0

``reporter.py``（Markdown 出力）::

    total_rate = (... ) if total_eval > total_profit else 0.0

同じ値を出すはずの計算が2箇所にあり、**ガード条件が異なっていた**。
評価額0・損益マイナスのポートフォリオで、ターミナルは ``+0.00%``、
Markdown は ``-100.00%`` と食い違っていた。

この食い違い自体は Issue #34（ゼロ除算ガードの修正）で
``formatter.py`` 側のガードを分母に合わせた際に解消している。
しかし**実装が2箇所に分かれている構造は残っており**、片方だけを
変更すれば再び分岐しうる。実際、この不具合はまさにそうして生まれた。

決定
----

合計の算出を ``sbipf_reporter.summary`` モジュールに一本化する。

* ``PortfolioSummary`` データクラスと ``summarize()`` 関数を新設する。
* ``formatter.print_summary()`` と ``reporter.format_as_markdown()`` は
  自前で集計せず ``summarize()`` を呼ぶ。
* 分母は取得金額の合計（ADR-0001 と同じ基準）。0 のときは 0.0 を返す。
* ``PortfolioSummary`` と ``summarize`` は公開APIとして ``__init__`` から
  エクスポートする。

なぜ「ガード条件を揃える」で済ませないか
----------------------------------------

Issue #34 の修正で症状は消えたが、それは片方の式を直しただけである。
同じ計算を2箇所に持つ限り、次に誰かが片方だけ触れば同じ問題が再発する。
根本原因は「ガード条件が違ったこと」ではなく「同じ計算が2箇所にあること」
なので、実装そのものを1つにする。

影響
----

* 出力値は変わらない。本変更は構造の整理であり、挙動の修正ではない。
* 公開APIに ``PortfolioSummary`` / ``summarize`` が増える。
  既存のフィールドとシグネチャに破壊的変更はない。
* 合計損益率を計算するコードはリポジトリ内で1箇所（``summary.py``）だけになる。

備考
----

本変更に対する回帰テストは、**修正前のコードでも通る**。症状が
ADR-0001 / Issue #34 の時点で既に解消されているためである。
テストの役割は「今の挙動を固定し、将来また分岐したら落ちるようにする」
ことであり、修正前後の差分を示すことではない。
